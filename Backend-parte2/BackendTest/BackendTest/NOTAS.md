Elegí Clean Architecture porque separa claramente las responsabilidades entre la API, la lógica de negocio y el acceso a datos, lo que facilita el mantenimiento, las pruebas y la escalabilidad de la aplicación; además, ya he trabajado anteriormente con esta arquitectura, por lo que me permite desarrollar la solución siguiendo buenas prácticas y manteniendo una estructura organizada

Aunque se pensó en implementar dapper en conjunto con Entityframework, se optó por Entity Framework Core como único mecanismo de acceso a datos, incluyendo la invocación del procedimiento almacenado sp_ProcesarAumentoSalarial aunque cuando Dapper ofrece una API más directa para ejecutar procedimientos almacenados, se priorizó la experiencia previa con EF Core, el tiempo disponible para el desarrollo y el riesgo de bugs al intentar algo en lo que se tiene menos experiencia; además EF Core soporta la ejecución de procedimientos almacenados.
